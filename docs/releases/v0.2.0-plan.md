# v0.2.0 release plan

## Goal and baseline

Prepare a focused, backward-compatible minor release from `v0.1.3` (`6dc2a86`).
The release corrects a run-on sentence in the package godoc and advances the
release workflow dispatch default to the current release.

## Scope

- Rewrite the final sentence of the `doc.go` package comment to eliminate the
  run-on construction and improve readability without changing any documented
  behavior or guarantee.
- Update the `release.yml` workflow dispatch default tag from `v0.1.3` to
  `v0.2.0`.

## Compatibility

- No exported function signature, wire-format, cryptographic, dependency, or
  interoperability-vector changes.
- No behavioral change to any public API, error sentinel, or lifecycle
  guarantee.
- The godoc edit is a prose-only correction; the documented contracts are
  preserved verbatim.

## Validation checklist

- [x] `go test -count=1 ./...` passes locally.
- [x] `go vet ./...` passes locally.
- [x] `gofmt -l .` is clean.
- [x] `go mod tidy` produces no module-file diff.
- [x] `git diff --check` is clean.
- [x] Markdown relative links resolve.
- [ ] Linux race suite passes in CI with `CGO_ENABLED=1`.
- [ ] Windows and remaining CI jobs pass on the release commit.
- [ ] Exact-tag release validation and external-consumer test pass.

## Release notes

DGProto Go v0.2.0 is a backward-compatible minor release.

- Corrected a run-on sentence in the package godoc without changing any
  documented behavior, guarantee, or public API.
- Updated the release workflow dispatch default to `v0.2.0`.
- No exported API, module dependency, wire-format, cryptographic, or

## Rollback

Never move or overwrite the published tag. If a regression is confirmed, revert
the affected commit on `main`, rerun all release gates, and publish a new patch
version.
