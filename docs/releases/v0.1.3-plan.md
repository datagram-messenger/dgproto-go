# v0.1.3 release plan

## Goal and baseline

Prepare a focused, backward-compatible patch release from `v0.1.2` (`e1ef069`). The release prevents direct `NewConnection` keepalive default overflow and corrects protocol capability prose to match serialized application-handler dispatch.

## Scope

- Preserve the effective default `KeepaliveTimeout` of twice `KeepaliveInterval` when that multiplication is representable.
- Saturate the direct `NewConnection` default at `time.Duration(math.MaxInt64)` when doubling would overflow.
- Share the overflow-safe default calculation with `NewServer` while preserving its existing validation and error behavior for impossible configured liveness windows.
- Add regression coverage for normal defaulting, the `math.MaxInt64/2` boundary, the first overflowing value, and a nonpositive/immediate-timeout guard.
- Clarify that multiplexing and pipelining do not imply parallel application dispatch or eliminate application-layer head-of-line blocking.
- Update the release workflow dispatch default.

## Compatibility

- No exported function signature, wire-format, cryptographic, dependency, or interoperability-vector changes.
- Representable keepalive defaults remain exactly twice the configured interval.
- Previously overflowing direct-connection defaults now saturate to the largest nonnegative duration instead of wrapping negative and becoming an immediate timer.
- `NewServer` continues to reject unrepresentable defaults and overflowing keepalive liveness windows with its existing errors.

## Release notes

DGProto Go v0.1.3 is a backward-compatible patch release.

- Fixed direct `NewConnection` keepalive defaulting so very large intervals saturate safely instead of overflowing to a nonpositive timeout.
- Preserved `NewServer` validation and error behavior for impossible keepalive liveness configurations through a shared overflow-safe helper.
- Corrected multiplexing and pipelining documentation to reflect serialized per-connection application-handler dispatch and possible head-of-line blocking.
- No exported API, module dependency, wire-format, cryptographic, or interoperability-vector changes.

## Rollback

Never move or overwrite the published tag. If a regression is confirmed, revert the affected commit on `main`, rerun all release gates, and publish a new patch version.
