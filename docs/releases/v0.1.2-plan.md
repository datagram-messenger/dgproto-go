# v0.1.2 release plan

## Goal and baseline

Prepare a focused, backward-compatible patch release from `v0.1.1` (`9ea9881`). The release fixes server timeout validation and corrects documentation that contradicted the established DGProto v1 wire behavior.

## Scope

- Normalize the effective default `KeepaliveTimeout` before validating `ReadTimeout` in `NewServer`.
- Reject duration overflow while calculating keepalive and liveness windows.
- Add regression coverage for default and explicit keepalive timeout configurations.
- Clarify that TCP framing is derived from the fixed header and has no outer length prefix.
- Resolve contradictory protocol prose in favor of the existing wire contract: little-endian integers and cryptographically random cleartext padding authenticated with the exact header as AAD.
- Replace stale release wording and update the release workflow dispatch default.

## Compatibility

- No wire-format, cryptographic, exported API, dependency, or vector changes.
- Runtime keepalive defaults are unchanged.
- Constructor validation is tightened only for configurations whose `ReadTimeout` is shorter than the effective liveness window.

## Release notes

DGProto Go v0.1.2 is a backward-compatible patch release.

- Fixed `NewServer` validation so `ReadTimeout` is checked against the effective default keepalive liveness window.
- Added overflow-safe keepalive duration calculations and focused regression tests.
- Corrected framing, integer-endianness, padding-authentication, and stale release wording in public documentation without changing established wire behavior.
- No exported API, module dependency, wire-format, cryptographic, or interoperability-vector changes.

## Rollback

Never move or overwrite the published tag. If a regression is confirmed, revert the affected commit on `main`, rerun all release gates, and publish a new patch version.
