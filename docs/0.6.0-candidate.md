# 0.6.0 hardening

This bounded release restores lifecycle, cancellation, and ownership invariants.
It is not a production certification. Publication requires independent final
review and fresh exact-commit CI; local evidence below does not replace those gates.

## Recommended release notes

- Server socket tracking now spans handshake, admission, and atomic runtime
  handoff. Shutdown closes admission networking even if the callback ignores its
  timeout; `Close` can still wait indefinitely for that callback to return.
- Accepted server workers reserve their wait-group entry under the shutdown gate,
  before goroutine launch. Shutdown cannot finish waiting across a zero-to-positive
  worker-registration race.
- TCP read and write lane acquisition is context-aware without per-waiter
  goroutines. Only an active owner watches cancellation and installs deadlines;
  watcher exit and deadline clearing still precede lane release. Canceled partial
  I/O does not promise stream reusability.
- Pending directional rekey frames retain independent payload/padding snapshots.
  `MarkRekeySent` rejects mutated frames and accepts the exact original bytes.
- Terminal outbound, control, close-request, and handler queues dispose pending
  references, including stopped connections. Producers hold shared enqueue leases;
  shutdown cancels blocked producers before acquiring the exclusive disposal
  lease. Channel receive transfers each item to exactly one writer/disposer, so
  each accepted write completion is published once. In-flight writers and handlers
  retain their own message until return; detached handlers are not killed and no
  secret-memory erasure is promised.
- `NewServer` rejects negative `HandlerShutdownTimeout`. Zero remains unbounded;
  positive timeouts detach stuck canceled message handlers, not admission hooks.

No exported signatures, sentinels, queue defaults, send acceptance/delivery
semantics, dependencies, strict MVP framing, Noise, AEAD, or rekey derivation
rules change. No vector fixture regeneration is included.

## Regression evidence

Before fixes, `go test -run TestHardening -count=1 -timeout=20s ./...` failed:
read/write calls canceled behind occupied lanes blocked until the watchdog;
mutated rekey payload and padding were accepted; stopped queues retained all
three message references; valid-key negative handler timeout was accepted.
`go test -run TestHardeningAdmissionSocketOwnership -count=1 -timeout=15s ./...`
failed both Close and Abort admission cases (peer read timed out).
The worker Add/Wait interleaving was source-proven, not dynamically reproduced.
A synchronized `testing/synctest` reservation regression checks that invariant.

Permanent regressions use I/O entry barriers, callback gates, cancellation
observation, a read-loop Ping barrier, and simultaneous producer/close/handoff
starts. Timers are bounded failure watchdogs, not scheduling sleeps. Stress
includes stopped and running write completions and pending running handlers.

## Local validation

Windows amd64, `CGO_ENABLED=0`; Go 1.26.5 and patched Go 1.25.10.
Commands executed from the module root unless noted:

```sh
gofmt -w connection.go server.go session.go tcp.go doc.go hardening_test.go
gofmt -l .
go test -count=1 ./...
go vet ./...
go test -tags dgproto_keylog -count=1 ./...
go test -run 'TestJSONWireVectors|TestWIRE|TestHS|TestSESS|TestP0' -count=1 ./...
go test -run TestHardening -count=30 -timeout=120s ./...
go test -run 'TestHardening|TestSend|TestConnection|TestServer|TestSession' -count=30 -timeout=120s ./...
git diff --check
```

Full/default, keylog, vet, vector/MVP and repeated focused checks pass locally;
Go 1.25.10 additionally exercises minimum-series compatibility. Module integrity
and tidiness are checked on both toolchains in a disposable copy containing only
tracked source plus the new public regression test:

```sh
go mod verify
go mod tidy
```

Both module hashes remain unchanged (go.mod and go.sum). Original checkout module
files are not modified by tidy.

Individual Go 1.26.5 fuzz campaigns, two workers each:

```sh
go test -run '^$' -fuzz '^FuzzTCPTransportReadFrame$' -fuzztime=60s -parallel=2
go test -run '^$' -fuzz '^FuzzFrameUnmarshalBinary$' -fuzztime=60s -parallel=2
```

TCP campaign passed 1,180,543 executions in 60 seconds with no new findings.
Frame campaign passed 1,310,689 executions in 60 seconds with no new findings.
`govulncheck -version` reports v1.9.0 with Go 1.26.5; `govulncheck ./...`
reports zero reachable vulnerabilities, with two imported-package and 24
required-module findings classified as not called. This is reachability evidence,
not a security audit or a claim that all dependencies have no advisories.

Local `go test -race -count=1 ./...` is unavailable on the validation host:
race requires CGO and a configured C toolchain. Linux race, Linux/macOS/Windows
execution and keylog/vulnerability checks must pass in fresh exact-commit CI
before publication. Historical CI for the previous release is not candidate
evidence. Independent interoperability and service-specific load/shutdown
evidence remain separate deployment gates.

## Separate unresolved pre-1.0 questions

These are deliberately **not** resolved by this candidate:

- ErrorMessage raw-string versus TLV specification ambiguity: preserve existing
  TLV bytes pending explicit compatibility/specification review.
- Replay versus authentication error precedence: preserve current behavior pending
  a separate normative/security decision.
- AllowedClients mutation/aliasing contract: no snapshot or mutation policy change.
- Multiple concurrent Serve calls and keepalive policy: no new policy imposed.

Admission/disconnect callbacks that ignore their own budgets can still block
server completion. Positive handler timeout only bounds the post-cancellation
message-handler wait, not total shutdown. Sending still means bounded queue
acceptance or local write completion, never peer processing/acknowledgement.

The GitHub release records exact-commit and exact-tag CI links and published-module
verification separately from the local candidate evidence above.
