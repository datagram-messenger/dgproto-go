# Go module 0.6.1 release candidate

This is a bounded patch to 0.6.0 for the existing draft DGProto v1 strict MVP.
The protocol draft version is unchanged; no exported API or wire-format changes
are introduced. Minimum Go remains 1.25.0. No tag or publication is implied by
these notes.

## Changes

- `Connection.Start` checks an already-canceled context before launching runtime
  loops. It synchronously stops the connection, disposes pending queues, closes
  `Done`, and preserves cancellation as the terminal cause. Repeated start/close
  calls do not restart it. Concurrent close retains first-cause semantics.
- Ordinary context cancellation records its terminal cause before attempting the
  close-frame write, preventing the resulting peer EOF from replacing that cause.
  This fix was already on main after 0.6.0; new regression coverage checks it.
- README onboarding, strict-MVP positioning, and branding were refreshed after
  0.6.0; these documentation changes introduce no protocol or API extension.
- `RekeyState.ComputeKeyConfirm` rejects uninitialized epoch zero with
  `ErrInvalidEpoch`. Valid successor confirmation bytes, derivation labels,
  maximum-epoch handling, and rejection of skipped/rollback epochs are unchanged.
  This is a helper correctness fix, not a claim of a remote vulnerability.
- `EncodeTLVs` writes directly into its owned, pre-sized output rather than
  allocating each field separately. Limits, validation order, error sentinels,
  field order, duplicates, zero alignment padding, and ownership are preserved.
  No pooling, unsafe code, decoder-capacity change, or cryptographic refactor is
  included. The decoder comment now cites normative padding section 2.4.
- Upgrade `golang.org/x/crypto` from v0.54.0 to v0.55.0, retaining
  `golang.org/x/sys` v0.47.0 and the Go 1.25.0 module requirement.

## Dependency review

The module was downloaded through the Go module tooling and verified with
`go mod verify`. Its recorded source is the Go project's
`https://go.googlesource.com/crypto`, revision
`f44d03d253a1503e51b059ca880867c51d878242`. The BSD-3-Clause license is unchanged.
The v0.55.0 module requires Go 1.25.0. The imported crypto directories have no
algorithm changes on amd64; `internal/poly1305` adds RISC-V 64 assembly and
updates architecture selection. That is an upstream RISC-V performance benefit,
not a measured amd64 crypto improvement or an asserted security fix.
Versions x/crypto v0.56.0 and x/sys v0.48.0 require Go 1.26.0 and are outside this
compatible patch scope. The application module diff changes only the crypto
requirement and its two checksums; no new application dependency is added.

## Release gates and limitations

Local Windows/amd64 validation passed the full tests, vet, formatting,
wire vectors/conformance/MVP/rekey tests, keylog-tag tests, and 100 lifecycle/rekey
repetitions using Go 1.26.5. Full tests also passed with minimum Go 1.25.0 and
patched supported Go 1.26.10. Module verification and tidy with a zero module diff
passed in a disposable canonical-LF worktree. `FuzzDecodeTLVs` passed a 60-second
campaign with two workers (725517 executions); no failing input was found.

Final Windows/amd64 checks with Go 1.26.5 repeated the baseline, vector/boundary
and keylog-tag tests, and module verification successfully. The complete
`go test -run '^$' -bench . -benchmem -benchtime=5s` suite passed (240.287 seconds);
this is a candidate-only gate, not a full-suite before/after comparison.
A temporary external consumer using an explicit local replacement passed a TLV
round trip and valid successor rekey-confirmation smoke test. It is not
published-module or independent-interoperability evidence.

`govulncheck` v1.9.0 on Go 1.26.10 reported zero reachable vulnerabilities and
zero findings in imported packages. Three module-only advisories remain in
unimported x/crypto SSH/OpenPGP packages (GO-2026-6355, GO-2026-6354,
GO-2026-5932). The SSH fixes require x/crypto v0.56.0 and Go 1.26.0; raising the
minimum Go version is outside this patch. A clean reachability result is not a
security audit, nor a claim that all packages in the dependency are advisory-free.

This document describes a candidate, not completed release validation.
Local tests do not replace fresh candidate CI on Linux, Windows, and macOS.
Linux race validation requires CGO and a C toolchain; it is not available on the
local Windows CGO-disabled host. The keylog build-tag job must also pass for the
candidate. Existing CI for earlier commits is not candidate evidence.

The release workflow validates an exact existing stable SemVer tag and runs an
external-consumer import smoke test using a local module replacement. That test
does not validate published-module availability, independent interoperability,
consumer API coverage, or application-specific load/security/shutdown budgets.
Tag pushes can publish automatically, so tag/push/publication remain separate,
maintainer-authorized steps after fresh candidate evidence is reviewed.
