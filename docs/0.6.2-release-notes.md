# v0.6.2 patch candidate

Local candidate only: no tag, push, release, or production certification.
The Go module version remains independent of the draft DGProto v1 specification.

## Changes and compatibility

- Keepalive acknowledgements are retained in bounded synchronized state for
  the outstanding nonce. Stale responses cannot displace a valid acknowledgement.
  The expectation is published before control enqueue, and cleared on valid
  acknowledgement, enqueue failure, and shutdown. The one-slot notification
  remains coalesced and the reader does not wait for maintenance. A ready timeout
  checks retained acknowledgement state before terminating the runtime.
- `DecodeTLVs` validates/counts fields before allocating exact descriptor storage,
  then copies values. Unknown/duplicate fields, opaque alignment padding, limits,
  nil output on malformed input, and ownership are unchanged.
- Added bounded reusable concurrent TCP echo coverage: 16 clients, 16 messages
  each, 4096-byte TLV values, and 16-byte padding in both directions. Workers and
  runtimes are joined; cancellation and network operations are bounded. This is
  an integration probe, not a throughput benchmark or service load certification.

No exported API, wire format, crypto construction, default timeout, queue limit,
minimum Go version (1.25.0), or dependency version changes. Existing first-terminal
cause behavior is retained. Keepalive nonce rollover skips the reserved zero
sentinel. Dependencies remain Noise 1.1.0, x/crypto 0.55.0, and x/sys 0.47.0;
the dependency review found no newer compatible version preserving the minimum Go.

## Regression evidence

The old runtime lost the matching authenticated response when maintenance was
withheld during stale/matching/stale, stale/matching, and flood bursts. The
matching/stale order is also covered. A controlled runtime interleaving held the
control enqueue lease while the reader processed a complete authenticated burst;
the old runtime then terminated with `ErrKeepaliveTimeout`. The patched runtime
proceeds to its next Ping. This is a synchronized synthetic interleaving, not a
claim that a production false timeout was observed. Immediate replies, notification
pressure, full control queue retry, rollover, concurrent methods, shutdown, and
retained first cause have focused coverage.

## Decoder measurements and decision

Same Windows/amd64 host and Go 1.26.10; no other test/build workload was deliberately
run during measurements. Each shape used `-benchmem -benchtime=5s -count=3`.
Numbers below are the observed ns/op ranges, not statistical confidence intervals.

| Shape | Old ns/op | Exact-count ns/op | Old / exact B/op | Allocs old / exact |
|---|---:|---:|---:|---:|
| Empty | 10.32–10.42 | 11.44–11.54 | 0 / 0 | 0 / 0 |
| One tiny field | 93.91–96.41 | 96.48–98.35 | 40 / 40 | 2 / 2 |
| Four tiny fields | 251.4–262.1 | 266.8–266.9 | 160 / 160 | 5 / 5 |
| 16383 empty fields | 285197–325613 | 378807–385545 | about 524290 / 524290 | 1 / 1 |
| Malformed length | 514.7–577.5 | 460.1–468.1 | 152 / 120 | 4 / 3 |
| One 64000-byte value | 117868–138813 | 18712–19016 | 581632 / 65568 | 2 / 2 |
| One maximum sequence value (65529 bytes) | 117588–121831 | 18561–19447 | about 589825 / 65568 | 2 / 2 |

A disposable initial-capacity-16 alternative was measured with the same commands.
For 16383 empty fields it used about 2527370 B/op and 17 allocations, taking
1051330–1151056 ns/op; for the long single field it used 66048 B/op and two
allocations, taking 18517–19145 ns/op. The cap is not shipped: repeated descriptor
growth penalizes dense input and introduces a workload-specific tuning constant.
Exact validated count gives predictable descriptor allocation and avoids allocating
copied values for an invalid suffix. Its second traversal costs CPU on dense tiny
fields (roughly 22% higher median for the many-empty case), and slightly on tiny
inputs. This tradeoff is deliberate; no pooling, unsafe, or speculative cap.
